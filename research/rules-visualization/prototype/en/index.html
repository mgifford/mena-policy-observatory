Rules-engine comparison: synthetic procurement policy

A fictional procurement rule encoded in Axiom RuleSpec and Legalese L4, with two visual views and a complete linear explanation. Nothing on this page is legal advice or existing law.

Synthetic research prototype. No legal effect. No real instrument is encoded. Translations are provisional and not official legal translations.

What the demonstration shows

The same five conditions and one threshold produce the same outcomes in both engines for complete facts, scope, exception, boundary and contradictory cases. Missing facts diverge: Axiom returns a missing-input error, while L4 models them as Indeterminate.

Ladder: evaluation order

The ladder is read from step 1 to step 5. Each step is a condition; the branch taken is stated in text.

  1. Step 1

    Are the required facts complete?

    If true
    Continue to coverage
    If false
    Indeterminate

    Citation: SP-3. Missing facts are not treated as false.

  2. Step 2

    Is the public body covered?

    If true
    Continue to scope
    If false
    Not applicable

    Citation: SP-1. Coverage is a condition, not a legal conclusion.

  3. Step 3

    Is the contract within scope?

    If true
    Continue to exceptions
    If false
    Outside scope

    Citation: SP-1. Scope is checked before the exception.

  4. Step 4

    Does an exception apply?

    If true
    Exception applies
    If false
    Continue to the threshold

    Citation: SP-1. An exception removes the requirement; it does not create a new one.

  5. Step 5

    Is the contract value at least USD 100,000?

    If true
    Open-source consideration required
    If false
    Requirement without open-source threshold

    Citation: SP-2. The boundary value itself meets the threshold.

Accessible text equivalent

This is the complete linear explanation, including every condition, branch, outcome and citation. It is not a summary of a visual-only decision.

  1. Step 1: Are the required facts complete? if false: Indeterminate (SP-3). if true: Continue to coverage.
  2. Step 2: Is the public body covered? if false: Not applicable (SP-1). if true: Continue to scope.
  3. Step 3: Is the contract within scope? if false: Outside scope (SP-1). if true: Continue to exceptions.
  4. Step 4: Does an exception apply? if true: Exception applies (SP-1). if false: Continue to the threshold (SP-1).
  5. Step 5: Is the contract value at least USD 100,000? if true: Open-source consideration required (SP-2). if false: Requirement without open-source threshold.

Unknown and missing facts

Missing required facts are not treated as false. L4 uses MAYBE and returns Indeterminate. Axiom has no undetermined literal in this RuleSpec; the determination status carries “indeterminate”, while the judgment outputs are not-holds when facts_complete is false. A missing input in Axiom is a request error.

Unsupported or out of scope

  • Deontic modality: Obligation, permission and prohibition are not first-class in RuleSpec. L4 can express them with PARTY, MUST, MAY and SHANT.
  • Amendment and version history: Effective dates can be encoded, but a reviewed instrument-version and amendment graph is external metadata; this prototype does not model it.
  • Translation provenance: Neither engine records official, reviewed or machine-assisted translation status. The interface translations here are provisional.
  • Real legal text and citation verification: All sources are fictional. No real instrument, provision, date or legal effect is encoded.
  • Contradiction detection: Both engines applied the ladder order to contradictory facts; neither reported a contradiction.

Limits of this prototype

The examples are synthetic; no real legislation is encoded. The graphs are generated from a curated presentation model, not automatically from the Axiom artifact. The L4 trace is a GraphViz DOT file; no SVG was rendered because GraphViz is not installed in this environment.

Accessibility findings

Static HTML and SVG, with one small progressive-enhancement script for keyboard scrolling; no canvas, drag, hover-only content or external JavaScript. Automated axe checks, keyboard tab order, scroll-key operation, 320 CSS px reflow, forced-colours and reduced-motion checks were run. Manual screen-reader, real 400% browser zoom and native Arabic/French review were not performed. Axe reported no violations; the SVG-text colour-contrast check was incomplete, so the actual foreground/background pairs were calculated manually at 13.39:1–16.45:1.
